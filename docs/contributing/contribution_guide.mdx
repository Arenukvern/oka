# Contributing

Thanks for your interest in oka! The project is agent-first: agents execute,
humans steer. That shapes how contributions work.

Please follow the [Code of Conduct](https://github.com/Arenukvern/oka/blob/main/CODE_OF_CONDUCT.md)
in issues, reviews, and community spaces.

## Setup

Install **Dart 3.14+** (`^3.14.0`; see `tool/ci/toolchain_versions.yaml`) and `just`
for contributor tooling. Flutter apps need **Flutter 3.50** and the Android SDK;
see the [build guide](../guides/build_and_config).

```bash
git clone https://github.com/Arenukvern/oka.git && cd oka
just install    # workspace dependencies (excludes the Flutter example)
just test       # dart test
just lint       # dart analyze --fatal-infos
```

Repository stewardship tools are implemented in Dart; shell commands are
entry points. The release and documentation gates use only the Dart SDK and
can run before dependency installation. See [`AGENTS.md`](../../AGENTS.md).

## Ground rules

1. **Non-negotiables** (see `AGENTS.md`):
   - The default build path must never shell out to `flutter build apk` /
     Gradle as success.
   - Only the no-Gradle pipeline exists; no cargo/Gradle fallbacks (ADR-0009).
2. **Behavior SSOT is code + tests.** Docs link to implementation; they never
   paraphrase it.
3. **Design forks need an ADR first.** If your change settles a trade-off,
   open/propose an ADR in `docs/decisions/` before coding.
4. **Phases are done only with evidence.** Update
   [`docs/PHASE_CHECKLIST.mdx`](../PHASE_CHECKLIST) with test references.

## Docs sync

After any behavior change, update the matching doc layer — see
[`docs/start_here/docs_map.mdx`](../start_here/docs_map):

| Change type | Update |
|---|---|
| Internal trade-off / architecture | `docs/guides/design_faq.mdx` Q&A and/or new ADR |
| Public API / usage / config key | `docs/guides/build_and_config.mdx` (copy-paste valid) |
| Settled strategic decision | `docs/decisions/NNNN-*.md` + index row |
| Phase-level completion | `docs/PHASE_CHECKLIST.mdx` evidence table |

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/) for readable
history. **Pub.dev versions are no longer driven by commit prefixes** — release
intent lives in reviewed `.changesets/` files (ADR-0054).

## Releases

The pub.dev train runs on **[dart_changesets](https://github.com/Arenukvern/dart_changesets)**
(ADR-0054; supersedes release-please for packages):

1. Land changes on `main` with `just lint`, `just test`, and `just check-contracts` green.
2. Add a `.changesets/<name>.md` intent file (e.g. `'oka': patch`, `'oka_core': minor`);
   dependents cascade when caret constraints no longer admit the new versions.
3. Merge the intent to `main`. [`.github/workflows/dart_changesets.yml`](https://github.com/Arenukvern/oka/blob/main/.github/workflows/dart_changesets.yml)
   assembles/updates the **version PR** with pubspec + changelog rewrites.
4. Review the version PR, re-run `just check-contracts`, then merge it.
5. The engine pushes **per-package tags** (`<package>-v<version>`) and dispatches
   [`.github/workflows/dart_changesets_publish.yml`](https://github.com/Arenukvern/oka/blob/main/.github/workflows/dart_changesets_publish.yml)
   (OIDC to pub.dev; upload order from `dart tool/release/train.dart list --publish`).

One-time pub.dev automated-publishing setup (per-package tag pattern) is in
[`skills/oka-maintenance/references/publishing.md`](https://github.com/Arenukvern/oka/blob/main/skills/oka-maintenance/references/publishing.md).

Local preflight (does not publish):

```bash
bash tool/ci/check_package_consumer.sh   # after a train upload, when debugging resolution
```

`oka_devices`, `oka_verify`, and the root workspace package stay
`publish_to: none` — they never upload. `oka_dart_kernel` is on the train:
it holds the dev session `oka dev` calls. Its first pub.dev upload is the
next release.

CI also runs `test/adr0011_apk_contents_test.dart` with
`OKA_REQUIRE_REAL_ANDROID_SMOKE=true`: missing prerequisites fail that job
instead of skipping the real APK/AAB builds.

## Contract gates

Run before every merge (`just check-contracts`):

| Gate | Checks |
|---|---|
| `check_package_changelogs.sh` | Train package changelogs match dart_changesets heading rules |
| `check_package_licenses.sh` | Every train package ships `LICENSE` |
| `check_docs_drift.dart` | Invariants documented; fast-settings keys present; `docs.json` sidebar resolves |
| `check_example_path_overrides.dart` | Example app path overrides cover reachable train deps |
| `check_train_package_lib_workspace_leak.dart` | Published `lib/` never imports monorepo-only paths |
| `check_duplicate_train_inventory.dart` | Train inventory SSOT stays in `tool/release/train_inventory.dart` |
| `check_no_personal_paths.sh` | No maintainer-local absolute paths in tracked files |
| `check_changelog_markdown.sh` | Markdown hygiene for changelogs |
| `run_actionlint.sh` | Workflow YAML lint |

## Pull requests

- Keep changes minimal and focused; match existing style.
- Add/adjust tests for anything that changes packaging or pipeline behavior.
- Run `just lint && just test && just check-contracts` before pushing.
- Benchmark-affecting changes: `just bench` (build) and `just bench-kernel`
  (kernel/live composition loop, delta pipeline, AOT pipeline exe); record
  machine JSON under `.steward/benchmark-summaries/` and summarize in
  `docs/evidence/`.
