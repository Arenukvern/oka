# Artifact store — git-LFS unblock & toolchain survey — 2026-10-11

Decision: [ADR-0043](../decisions/0043-artifact-store-delta-chains).
Usage: [artifacts guide](../guides/artifacts).

## Evidence

- **Git-LFS blocking incident.** GitHub rejects any file over 100 MB that
  is not in LFS — and the blob blocks **every** push that carries it in
  history, even after `git rm --cached` (history keeps the blob). The
  `last_answer` migration carried a 124 MB `main.dart.dill` (later a
  129 MB one) in history. Unblocked with:

  ```bash
  git bundle create /tmp/backup.bundle --all      # safety first
  git filter-repo --force --invert-paths --path-glob '*.dill'
  git remote add origin <url>                     # filter-repo removes it
  git push origin <branch>
  ```

  `filter-repo` rewrites commit ids on the filtered branches — land or
  communicate in-flight work first. This is the operational motivation
  for the store's core posture: compiled outputs never enter git; git
  keeps at most a ~200-byte provenance pointer.

- **Machine toolchain survey.** The workstation had **brew dart**
  (3.13.2) alongside **fvm flutter's dart** (3.13.4). A JIT dill must be
  *built and booted* by the same SDK generation — a skew compiles fine
  and then dies mid-reload. Rules that came out of it: the harness
  snapshot lane pins both sides (`DART_BIN`, default
  `/opt/homebrew/bin/dart`) and nothing may override one side only;
  anything pairing a source checkout with a running VM checks versions
  first, and the guard names the mismatch and the exact fix command.

## Scope and limits

- The harness-side consumers referenced by this incident —
  `build_owner_snapshot.sh` and
  `tool/supervisor_beat/bin/artifact_store.dart` — live in the external
  **ecsai_harness** repository, not in oka. oka ships the store
  (`packages/oka_artifacts`); those scripts are its first wired consumer
  on the harness side.
- The brew/fvm skew notes describe one workstation, not a product
  contract; the durable rule is the same-SDK-generation pairing
  requirement, enforced where relevant by version guards.
