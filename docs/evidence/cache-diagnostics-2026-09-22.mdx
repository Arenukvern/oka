# Cache diagnostics validation — 2026-09-22

Implemented the API-first plan in [ADR 0021](../decisions/0021-composable-cache-diagnostics).
Three lighter subagents handled core metadata, Android AVDs and Chrome profiles;
the primary agent integrated the contract, Apple adapter, CLI and review fixes.

## Delivered

- Exported `CacheDiagnostics`, provider/context/report contracts and first-party
  providers. Custom providers compose without changing CLI dispatch or enums.
- Detailed/filterable cache diagnostics with namespaced JSON metadata, timestamps,
  observation sources, project-qualified relations and inert argv/cwd actions.
- Partial registry reads preserve valid siblings and report missing projects.
  Ordinary stats does not write registry metadata. Cleanup remains strict.
- PID-zero leases remain unknown and survive reconciliation; new Chrome leases
  retain canonical profile paths and session names, including temporary profiles.
- Android stored metadata and component sizes; browser profile attribution;
  Apple stored identity metadata using XML/binary plist decoding. No runtime
  device state is inferred from directory existence.

## Limits

No live emulator/browser/simulator acceptance run, semantic ADB/CDP/simctl probe,
MCP server or interactive dashboard was performed or implemented. Logical byte
counts are not allocated disk usage. Registry and process observations are
snapshots, not locks or a supervisor. Temporary profile measurements outside
storage discovery are diagnostic details, not additions to overall storage totals.
No user cache was deleted and the installed global CLI was not replaced.
