# Supervisor — govern processes declaratively

**TL;DR:** Declare what should run (services that stay up, jobs that run once).
Run **`oka supervisor apply plan.json`** for one converge pass — observe, diff,
act, write records, exit. No resident daemon in the shipped rung.

Package: [`packages/oka_supervisor`](https://github.com/arenukvern/oka/tree/main/packages/oka_supervisor).
ADRs:
[0040](../decisions/0040-declarative-supervisor) (engine),
[0041](../decisions/0041-supervisor-adoption-ladder) (L0 CLI + plan codec),
[0042](../decisions/0042-resident-supervisor-ota-runtime-owner) (proposed R2 —
not implemented).

Related: [Process lifecycle](../guides/process_lifecycle) (leases, `oka
processes`, `oka stop`) — the supervisor composes the same lease substrate for
the `process` provider.

## Who uses this and why

The supervisor targets **long-lived or repeatedly-run local processes** that
today are started by hand, shell scripts, or README conventions — and fail
silently when they die.

| Scenario | What you declare | What converge gives you |
| --- | --- | --- |
| **Local API or MCP server** for dev | `shape: service`, readiness probe, restart budget | Start once per pass; restart within `maxRestarts` after crash; `giveUp` when budget exhausted |
| **One-shot or periodic job** | `shape: job`, optional `interval` trigger | Run to success (or fail visibly); records last outcome |
| **Repo-governed automation (L2 direction)** | `supervisor/plans/*.json` in git | `oka supervisor check` in CI — plan vs machine records, no side effects |
| **Embedding in Dart** (tools, tests, apps) | `DesiredState` + your `ProviderFactory` | Same planner/registry as the CLI; see `example/supervise_demo.dart` |

It is **not** a cron parser, port allocator, log analyzer, or multi-host
orchestrator. Command-lane watchers (ADR-0038) stay separate; the supervisor
does not add a second file watcher in v1 (ADR-0040).

## CLI quick start

From any project directory (records are scoped to that project root):

```bash
# 1. See what this machine already recorded for the current project
oka supervisor status
oka supervisor status --json    # agents / CI parsers

# 2. Dry-run a plan (validation + planned actions, no processes touched)
oka supervisor apply plan.json --dry-run

# 3. One converge pass (start/stop/restart per plan + policy)
oka supervisor apply plan.json

# 4. Optional: append JSONL lifecycle facts
oka supervisor apply plan.json --evidence /tmp/supervisor-facts.jsonl

# 5. Drift gate: committed plan vs records (read-only; exit 1 on mismatch)
oka supervisor check plan.json
oka supervisor check plan.json --json
```

**Provider seam:** `oka supervisor apply` only implements the **`process`**
provider. Each spec must include `env.command` (executable) and optional
`env.args` (space-separated). Any other `provider` name is rejected before
spawn (`supervisor_command.dart` preflight).

### Minimal plan (job)

This matches the contract tests in `packages/oka/test/supervisor_command_test.dart`:

```json
{
  "version": 1,
  "specs": [
    {
      "id": "true-job",
      "provider": "process",
      "shape": "job",
      "env": { "command": "/usr/bin/true" }
    }
  ]
}
```

```bash
oka supervisor apply plan.json --project .
```

### Service-shaped plan (long-running process)

Schema reference and field kinds: `SpecCodec` doc comment in
`packages/oka_supervisor/lib/src/codec.dart`.

```json
{
  "version": 1,
  "readinessBudgetMs": 30000,
  "specs": [
    {
      "id": "demo-api",
      "provider": "process",
      "shape": "service",
      "policy": { "maxRestarts": 3, "restartWindowS": 120, "revision": 1 },
      "readiness": { "kind": "handshakeLine", "pattern": "listening on" },
      "env": {
        "command": "/usr/bin/python3",
        "args": "-m http.server 8080"
      }
    }
  ]
}
```

After a successful apply, records live under
`~/.oka/supervisor/records/<scope>/<id>.json` where `<scope>` is derived from
the project root (`MachineRegistry.scopeFor`).

## Library quick start (Dart)

For custom providers (not limited to `process`), compose in Dart and call
`Supervisor.converge` directly:

```bash
cd packages/oka_supervisor && dart run example/supervise_demo.dart
```

That demo: start a real `/bin/sh` service → readiness → kill → budgeted restart
→ JSONL facts. Provider mechanics use `LeasedProcessProvider` from `oka_core`;
policy stays in `oka_supervisor`.

Typed authoring (no JSON file):

```dart
const desired = DesiredState(specs: [
  ComponentSpec(
    id: 'api',
    providerName: 'leased',
    policy: SupervisionPolicy(shape: SupervisionShape.service, maxRestarts: 3),
  ),
]);

final report = await Supervisor(projectRoot: projectRoot).converge(
  desired: desired,
  factory: myProviders,
  apply: true,
);
print(report.describe());
```

Pass `apply: false` for dry-run. Round-trip a plan file with `const SpecCodec()`.

## Common workflows

### 1. “Is my declared server still what the machine thinks?”

```bash
oka supervisor status --json | jq .
```

Status is **records-only** — it does not converge. Corrupt record files are
listed explicitly (human output and `--json`).

### 2. “Apply this plan once after deploy”

```bash
oka supervisor apply deploy/plan.json --evidence .oka_cache/supervisor.jsonl
```

Each invocation is **one pass** (ADR-0040). For steady state you re-invoke
converge (script, CI job, or a future resident rung — not shipped).

### 3. “CI: repo plan matches reality”

Commit a plan (ADR-0041 L2 convention: `supervisor/plans/*.json` is the
documented shape; adoption is per-repo). In CI, after a machine has converged:

```bash
oka supervisor check supervisor/plans/dev-stack.json --json
```

`check` never starts or stops processes. It fails on corrupt records, revision
drift (`revision` bump in plan without re-converge), absent **service** specs,
or jobs whose last run failed (`supervisor_command_test.dart`).

### 4. Codemap lanes (read-only projection)

Foreign runners can project lane receipts into supervisor findings without
executing oka plans:

```bash
cd packages/oka_supervisor
dart run tool/codemap_projection.dart --snapshot lanes.json --receipts receipts/ --check
```

`--check` exits non-zero on `overdue`, `unrun`, or `corruptReceipt` (see package
README). This is a **projection**, not `apply`.

## The five laws (operating rules)

1. **Converge is explicit** — one pass per call; no background reconciler in R1/L0.
2. **Restarts are budgeted** — `maxRestarts` within `restartWindow`; then `giveUp`
   until `policy.revision` changes.
3. **Kill rights = spawn lineage or cession** — `killPolicy: none` → findings only.
4. **Registry is advisory** — records written before spawn; not kill authority.
5. **One fact envelope** — `supervisorFinding` + substrate lifecycle events in JSONL.

## Roadmap (derived from ADRs — not a commitment schedule)

| Rung | Intent | In this repo today |
| --- | --- | --- |
| **R1 + L0** | Specs, planner, registry, `SpecCodec`, `oka supervisor *` | **Yes** — tests above |
| **L1 mesh** | `statusJson` snapshots over a mesh transport | **No** — gated (ADR-0041); external consumer designs only |
| **L2 git** | Committed plans + `check` in CI | **Mechanism shipped** (`check`); folder convention is opt-in per repo |
| **L3 server** | Multi-host, signed cession | **Undesigned** — needs new ADR superseding ADR-0001 + ADR-0030 §5 |
| **R2 resident** | Always-on converge loop + OTA runtime owner | **Proposed only** — [ADR-0042](../decisions/0042-resident-supervisor-ota-runtime-owner); entry criteria listed there |

ADR-0041 names external product integrations (for example embedding apps on
device). Those are **not** validated in the `oka` repository; treat them as
downstream consumers of the same plan/record artifacts, not as shipped oka
features.

## Deliberately out of scope (v1)

Cron expression parsing · second file watcher · port allocation · interpreting
stdout/stderr for policy · remote multi-machine actuation without ADR-0042.

## Codemap index worker

[ADR-0045](../decisions/0045-codemap-index-worker-supervision.mdx) adds an explicit
native worker recipe, independent of read-only command-lane projection.
`CodemapIndexRecipe` and `CodemapIndexProvider` compose leased process mechanics
with Codemap's revision receipt. The [package manual](../../packages/oka_supervisor/README.md)
contains the API and finite-pass recipe.

A live worker may report pending or blocked index health. These states retain
the worker and expose the blocker; they do not consume restart budget.
Unverifiable receipts stay unknown. Verified process death or explicit
configuration change follows normal lifecycle convergence. This does not
supersede the gated resident-supervisor decision.

### Argument and job-completion qualification

Use `env["args-json"]` with a JSON string array for exact argv, including paths with
spaces and literal quotes or dollar signs. Legacy `args` remains space-split; declaring
both is refused before effects. No shell expansion is performed. CLI job providers
now use `LeasedProcessProvider(runToExit: true)`: returned start means exit zero,
not merely a spawned or ready child. Nonzero exit and cancellation fail the job.
Typed consumers must select run-to-exit behavior for jobs as well.
