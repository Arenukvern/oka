# Live update guide

Change a running Dart program without restarting it. One composition —
a `LivePatchSpec` (units, targets, probes) — covers the developer loop
(JIT) and the production path (AOT). Behavior SSOT is code + tests
(`packages/oka_update/test/`); this guide links, it does not paraphrase.

Stack: `oka_dart_kernel` (unit graph, delta compiler, pipeline exe) +
`oka_update` (session, targets, receipts) — experimental, not on pub.
Design: ADR-0031/0032/0034/0035; evidence:
`docs/evidence/deferred-patch-units-spike-2026-10-01.mdx`.

```dart
final receipt = await runLivePatch(spec, compile: pipelineDeltaCompiler(toolchain), root: appRoot);
```

## Developer paths (JIT — live, state preserved)

### The converged session: `oka run dev`

One command boots the app and owns the loop (ADR-0037 §6 — r is oka's
unit-delta lane; R is the platform restart):

```bash
oka run dev --platform macos --project ~/xs/storage_problem/last_answer
oka run dev --platform web  --project ~/xs/storage_problem/last_answer \
    --port 8188 --open-browser
```

| Command | Lane | What happens |
|---|---|---|
| `r [file]` | **oka** | a `.dart` file: the changed library is compiled by the app's own frontend and applied over the VM service (DevFS + `reloadSources` + reassemble on desktop; dwds on web) — receipt per reload, probes verified. A **declared asset**: bytes sync into the engine's asset dir + `ext.flutter.evict` (live freshness is engine-blocked on macOS; `R` applies) |
| `R` | platform | the serving `flutter run` session hot-restarts the app |
| `q` | — | clean quit |
| `--watch` | oka | every saved file in the watch set applies automatically (dart sources + declared assets — the invisible loop) |
| `--probes <f>` | oka | declarative probe specs verified after each reload |
| `--json` | oka | receipts as JSON lines (agents) |

macOS and web are proven on last_answer (`tool/gate_run_dev.sh`); the
android surface stays `oka dev` (ADR-0011 daemon) until oka owns a
device build path. AOT dev rehearsal is the `slotSwap` lane
(`gate_aot_slots.sh`) — a different, bounded contract.

### The API surface

Pick the loop that matches how you work:

| You are… | Use | What it does |
|---|---|---|
| editing one file | `applyChange(spec, changedFile: …)` | compiles that file's library as the delta, applies, verifies |
| saving continuously | `LiveWatcher(…)` + `start()` | watches, debounces, applies on save; silent on success |
| scripting a step | `runLivePatch(spec)` | one shot: patch → compile → apply → probes → receipt |
| a terminal, no Dart | `oka live patch --spec spec.json` | the declared verbs as a CLI (`oka live verify\|patch\|watch`; delegates to the experimental runner, ADR-0036) |
| a server process (watcher for its lifetime) | `tool/oka_live_watch.dart --spec spec.json --watch <dir>` | JSON-line receipts on every save — supervisor-tailable, server shape |
| multi-revision | `runLivePatch` per revision | endless loop: continue / reset / continue (see `gate_endless_loop.sh`) |

Every run ends in a receipt: per-target apply mode, probe flips, and the
continuity hold. A probe that must not change (`hold: true`) is the
no-restart proof; a probe with `expect:` is the change proof.

Targets are plain data (`TargetSpec`): a stock VM or `dart run` server
(`reload`), an Android device (DevFS), a web app (dwds), a Flutter
desktop app, an MCP stdio server — see `gate_live_e2e.sh` and
`gate_live_products.sh` for a worked example of each. Live session wire
facts: `skills/oka-kernel/references/toolchain.md` §11–12.

### JIT dangers (each one bit us; each is guarded)

- **`const` values survive reloads.** Patch function bodies or
  constructor defaults — never a `const` field's value.
- **URI coherence.** The delta must be compiled under the *same package
  config the target loads* (`appPackagesConfig`). Mismatch = reload
  "succeeds", nothing changes.
- **One seam per revision.** A delta carries the entry library's
  recompiled set only. Two independent seams → two revisions (the
  endless-loop shape), or one entry importing both.
- **Flutter-hosted VMs: compile with the app's own frontend**
  (`frontend_server_aot` + flutter_patched_sdk). A foreign-frontend
  delta isn't refused — desktop `reloadSources` falls into the dead
  kernel-isolate lane, and `_reloadKernel` `RELEASE_ASSERT`s and
  **kills the app** (desktop AND android; proven both). Apply via
  `reloadSources {pause: false, rootLibUri}` on desktop,
  `_reloadKernel(devfs)` on devices — `toolchain.md` §12.
- **Don't interrupt an apply.** Patch markers land on real source files;
  drivers restore in `finally`, gates restore via git. A killed run can
  leave markers — `git status` before committing.
- **Reload is not state migration.** Existing objects keep their fields;
  your probes are the contract that the right thing changed.
- **Patching a build tool invalidates its own caches** (oka's build is
  self-referential). Host live-patch sessions on non-build commands.

## Production path (AOT — no VM service, no JIT)

Production processes don't expose a VM service. Updates ride **staged
artifacts**, not wire reloads:

| Lane | Mechanism | Status |
|---|---|---|
| `slotSwap` | pre-provisioned loading-unit part ELFs loaded lazily in-process on an update signal | **proven** (`gate_aot_slots.sh`): r1 → r2, same pid. Bounded slots per process |
| `restartHandoff` | snapshot swap; new process takes over the socket (SO_REUSEPORT) | **proven on linux** (60/60, 0 refused); macOS needs fd passing |
| `nextLoad` (web) | pointer flip + chunk fetch at next load | designed (G4 web gate); oka-owned DDK session pending |

AOT dangers:

- **Slot budget is per-process.** Unbounded revision streams must ride
  `restartHandoff`, not slots.
- **Mach-O has no unit packaging** — use ELF targets (macOS/linux
  android); iOS is an embedder seam.
- **Delta versions must match the runtime** — cross-version kernels fail
  to parse (see JIT dangers; in AOT it manifests at load time).
- **Delivery is not built yet.** Eligibility, manifests, signing,
  `UpdateClient` are ADR-0034's ladder — until they land, "production"
  means the harness paths above, not a shipped updater.

## Shipping invisibly: `oka ship` (the air channel)

A patch the developer writes by hand is a bug (ADR-0037 §1). Declare
units **once** in the composition, then the whole loop is one command —
revision, manifests, eligibility, deltas, and the channel tree are all
derived; the receipt is the interface:

```bash
oka ship                     # derive everything from the working tree
oka ship --dry-run           # plan + receipt, publish nothing
oka ship --snapshot app.so   # also attach the whole-revision AOT set
oka ship --snapshot-from-build build/web            # archive a build output
oka ship --max-chain-bytes 262144                   # seed publisher policy
```

Units are declared in `tool/patch_units.dart` (plain project Dart):

```dart
import 'package:oka_update/oka_update.dart';

final patchUnits = UnitsSpec(revision: 'baseline', units: [
  PatchUnit(name: 'feature', libraries: ['lib/units/feature.dart']),
]);
```

The channel is a content-addressed tree + `pointer.json` (default
`build/oka-channel/`) — push it to a git branch, gh-pages, or any static
host; nothing in the wire format knows which (ADR-0037 §2). Publishing to
a local git repo is built in (orphan branch; the repo's working tree is
untouched):

```bash
oka ship --publish-git ~/path/to/origin-repo   # branch: oka-channel
```

Bare repos and remote URLs publish through a throwaway clone + force-push
(the publisher owns the branch) — same command. For a signed channel:

```bash
oka ship --generate-signing-key ~/.oka/signing-key   # once; prints the trust anchor
oka ship --signing-key ~/.oka/signing-key --publish-git <repo>
```

Embed the printed trust anchor (public key) in the app at build time;
`UpdateClient` then refuses unsigned pointers/manifests, foreign keys, and
tampered bytes. Staged updates ride the boot watchdog
(`StagedUpdateJournal`): the fetched set lands in `staged/`, the app's
startup beacon promotes it (`journal.commit()`) or discards it
(`journal.rollback()`) — a staged update can never brick an install.

Clients resolve their own update with `UpdateClient` + `planChain`:
migration chain within the declared byte/revision thresholds, head
snapshot above them, typed refusals at store boundaries. The snapshot is
**derived, not hand-picked** (ADR-0037 G-AC6): the ship projects the
chain a fresh client would apply (`chainLoad`) and, when it would overrun
the pointer policy, derives a whole-revision snapshot — `--snapshot-from-
build <dir|file>` archives a build output, no value compiles the whole
kernel from the entrypoint — and attaches it to the head node. A branch
checkout is just a file tree — `FileChannelSource` reads it. Contract-
or core-touching diffs refuse with the store-lane alternative — that is
the API being honest, not broken.

Proven end-to-end on last_answer's real engine (units declared once,
invisible ship while the engine ran, fetched delta applied over the VM
service, boot state held, one pid):

```bash
packages/oka_dart_kernel/tool/gate_air_channel.sh   # engine: ship -> git branch -> VM apply
packages/oka_dart_kernel/tool/gate_air_web.sh       # web: ship -> release build -> static host -> HTTP client
```

Design: ADR-0037. Code + tests:
`packages/oka_update/lib/src/channel/` + `packages/oka_dart_kernel/tool/oka_ship.dart`.

## What's next

In dependency order (execution view: [PHASE_CHECKLIST](../PHASE_CHECKLIST)):

1. **`oka run dev --platform android`** — all pieces exist (oka builds
   the APK, the ADR-0011 daemon owns install/launch, the device lane
   applies deltas and syncs assets over DevFS); wiring them into the
   session retires the two-command android loop.
2. **`oka build` emits the head snapshot** so `oka ship` stages it with
   no flag — the last wording gap in G-AC6; rides ADR-0030 composition.
3. **Analyzer-backed unit fingerprints** (ADR-0034 G4) replace the
   prototype declaration-line fingerprints (fail-closed today).
4. **Web in-app adoption + unit generator** (ADR-0031 gate 1): the
   bootstrap that consumes the channel at page load, plus
   barrels/registry codegen.

Research lines — deliberately not roadmated, each needs its own ADR
before any coding: per-unit AOT over the air (G-AC9: sdk#64162, embedder
`Dart_SetDeferredLoadHandler`, S2 registry), macOS fd-passing handoff,
unbounded AOT revision streams, and **live asset freshness** (the
engine's asset mapping cache ignores `ext.flutter.evict` on macOS — an
engine seam, flutter has the same ceiling; ADR-0037 §6b).

Agents don't need shell for the loop: `oka_update/live_agent.dart`
declares `oka.live.patch` / `oka.live.watch` / `oka.live.verify`
(descriptors + dispatch, receipt JSON out) — ADR-0036.
