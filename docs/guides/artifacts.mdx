# Artifacts — bytes out of git, delta chains in the store

**TL;DR**: compiled outputs (dills, snapshots) never enter git. `oka
artifacts put` records them into `~/.oka/artifacts` as delta chains;
git keeps at most a ~200-byte provenance pointer. ADR:
[0043](../decisions/0043-artifact-store-delta-chains.mdx).
Package: `packages/oka_artifacts`.

## The 60-second version

```bash
oka artifacts put build/app.dill --name app-dill \
  --pointer build/app.dill.json          # optional shared warm start
oka artifacts materialize app-dill -o build/app.dill
oka artifacts verify app-dill
```

Snapshot cadence is automatic: zstd deltas append while they cost
≤35% of the full size; ratio, depth (8) or cadence (20) roll a fresh
snapshot. Identical content is a no-op write.

## Adopting in a repo (the 4-step recipe)

1. Untrack the binaries: `git rm --cached <files>` + `.gitignore` glob.
2. Wire the producing lane/script to `oka artifacts put` (or the
   `ArtifactStore.record` API) — best-effort, failure-tolerant.
3. Optionally commit the pointer file where the binary used to be.
4. Consumers read via `materialize` **or** rebuild from source — the
   dill is a warm-start hint, never a requirement.

## Incident note

A 124 MB dill in git history once blocked **every** push (GitHub rejects
blobs over 100 MB outside LFS, even after `git rm --cached`); the
`git filter-repo` unblock and the brew/fvm Dart-skew toolchain survey that
shaped the same-SDK-generation pairing rules are recorded in
[artifact-store-lfs-unblock-2026-10-11](../evidence/artifact-store-lfs-unblock-2026-10-11).
